# 签名与发布

本文是仓库内的**流程文档**，不含任何密码。密钥本体与口令见交接文档
（在手机 `/sdcard/Download/DSH-Go/纸鸢-签名密钥/交接说明.md`，不进仓库）。

## 证书

| 项 | 值 |
|---|---|
| 包名 | `app.paperlite.chat` |
| 别名 | `zy` |
| Owner | `CN=ZhiYuan, O=ZY, C=CN` |
| 有效期 | 2026-11-20 → 2054-04-07 |
| 证书 SHA-256 | `33:44:D2:E0:C2:50:60:9F:9D:28:7A:25:D4:DF:9F:30:C5:EE:D4:D0:82:5F:8F:2E:BA:6C:4B:FB:C2:B3:03:4E` |
| 密钥库 | `keystore.jks`（JKS，不入库） |

换机器/换人接手时，**必须用同一个 keystore 签名**，否则现有用户会收到
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`（签名不一致），只能卸载重装、本地数据全丢。

## 构建

```bash
cd client
ANDROID_HOME=/path/to/android-sdk \
AAPT=/usr/bin/aapt AAPT2=/usr/bin/aapt2 \
D8=/path/to/android-sdk/build-tools/34.0.0/lib/d8.jar \
KEYSTORE=/path/to/keystore.jks KS_PASS=<storepass> KS_ALIAS=zy \
SERVER='ws://114.55.230.190:8080' \
UPDATE_SERVER='http://114.55.230.190:8080' \
bash build.sh <版本名> <版本号>
```

产物：`dist/zhiyuan-<版本名>.apk`（已签名）。

- `AAPT`/`AAPT2` 必须显式传：x86-64 主机上直接调 ARM 版 SDK 会 `Exec format error`。
- 版本号要动两处：`client/AndroidManifest.xml`（`versionCode`/`versionName`）
  与 `client/app/version.js`（`APP_CODE`/`APP_VERSION`），且必须递增。

## 校验

```bash
apksigner verify --print-certs dist/zhiyuan-<版本>.apk
# 证书 SHA-256 应等于上表那一串
```

## 发布

1. APK → `root@114.55.230.190:/opt/zhijian/server/data/apk/zhiyuan.apk.new`，
   再 `mv` 覆盖 `zhiyuan.apk`；`chown chat:chat`、`chmod 644`
2. `data/version.json` 写 `{code, name, notes, url, size, sha256}`
   - `url` 必须是完整地址 `http://114.55.230.190:8080/download/apk`
     （留空会退化成 `127.0.0.1:8080`，手机收不到更新）
3. 服务端每次 `/version`、`version_check` 都重读文件，不需要重启
4. 四处 sha256 一致：本机 `dist/`、手机 `/sdcard/Download/DSH-Go/`、服务器、仓库 `apk/`
5. 提交 + tag + 推送（`apk/*.apk` 被 gitignore，需 `git add -f`）

## 密钥保管

- 丢了 = 所有用户必须卸载重装（换 key 等于换作者），没有补救。
- 泄漏 = 别人能发出你用户手机无条件接受的更新包。
- 建议离线介质 + 密码管理器各留一份；`.gitignore` 已排除 `*.jks`。
