# 纸鸢模块接口（13.61 起）

模块（插件）= 一段跑在手机上的 JS + 一个描述文件。装好后从「我的 → 模块 → 我的模块」打开，
模块界面画在独立的全屏页面里，宿主只通过 `ctx` 给能力。

> 安全前提：模块代码在用户自己的手机上运行，**能做的事和 App 本身一样多**（读本地聊天记录、
> 替用户发消息）。所以装模块时会把模块声明的权限摆给用户看，用户点确认才会打开。
> 服务端**不执行**模块代码，只负责存放模块包、市场索引和模块专属存储。

## 1. 模块包

上线时是两份文本：

```
manifest.json   { ... }        // 模块描述
client.js       function mount(ctx) { ... }
```

`manifest.json` 字段：

| 字段 | 说明 |
|---|---|
| `id` | 必填，小写字母开头，`[a-z0-9_-]{3,25}`，**全局唯一**，上传后不能改（改 id 等于新模块） |
| `name` | 显示名，≤24 字 |
| `ver` | 版本号字符串，自己维护 |
| `desc` | 一句话简介，≤160 字 |
| `author` | 作者名，≤20 字 |
| `perms` | 权限声明数组，可选 `store` / `ui` / `notify` / `image` |
| `icon` | 一个 emoji 或单个字符，列表里当图标 |
| `minApp` | 需要的最低 App versionCode（当前 190，小于它就不让装） |

## 2. client.js

文件里定义三个**全局函数**（不是 export，直接写 function）：

```js
function mount(ctx) {
  // 必选。ctx.el 是一块属于这个模块的空 div，往里面画界面。
  ctx.setTitle('掷骰子');
  ctx.el.innerHTML = '<button id="roll">掷一次</button>';
  document.getElementById('roll').addEventListener('click', function () {
    ctx.toast('掷出了 ' + (1 + Math.floor(Math.random() * 6)));
  });
}

function onMessage(d, ctx) {
  // 可选。收到别的用户通过 ctx.broadcast 发来的消息。
}

function unmount(ctx) {
  // 可选。用户离开模块页 / 卸载模块时收尾（清定时器之类）。
}
```

### ctx 能力表

| 成员 | 说明 |
|---|---|
| `ctx.id` / `ctx.manifest` / `ctx.version` | 模块 id、描述对象、当前 App versionCode |
| `ctx.el` | 模块自己的容器 div |
| `ctx.html(str)` | 等价于 `ctx.el.innerHTML = str` |
| `ctx.setTitle(t)` | 改运行页标题 |
| `ctx.me()` | `{ uid, nick, avatar }` 当前登录用户 |
| `ctx.send(obj)` | 发一条原始协议（**慎用**，标准协议见服务端代码） |
| `ctx.broadcast(body)` | 发一条 `mod_relay`：所有装了同模块的在线用户都会收到（服务端按模块名转发） |
| `ctx.onMessage(fn)` | 等价于写 `onMessage` |
| `ctx.store.get(key, cb)` | 服务端模块存储读，`cb(value)`；按用户隔离 |
| `ctx.store.set(key, value, cb)` | 写；`value` 为 `null` 表示删除 |
| `ctx.local.get(key, def)` / `.set` / `.del` | 本机存储，key 自动加前缀 `pl.mod.<id>.` |
| `ctx.toast(msg)` | 短提示 |
| `ctx.notify(title, text)` | 系统通知（需要 `notify` 权限） |
| `ctx.imgSrc(path)` | 把服务器图片路径转成可访问 URL |
| `ctx.viewImage(url)` | 全屏看图 |
| `ctx.confirmTap(key)` | 「4 秒内再点一次」防误删，返回 true 表示这是第二下 |

注意：`client.js` 在 `new Function` 里执行，拿得到 `ctx`，但**不要依赖宿主内部变量**
（`S`、`wsSend` 这些不是接口，随时会变）。

## 3. 服务端协议（模块相关）

| 协议 | 谁用 | 说明 |
|---|---|---|
| `mod_index` | 客户端 | 拉市场列表（已上架 + 自己上传的 + 开发者能看全部待审） |
| `mod_get {id}` | 客户端 | 下载模块（manifest + code） |
| `mod_upload {manifest, code}` | 上传面板 | 普通用户 → `pending`；开发者 → 直接 `approved` |
| `mod_review {id, ok}` | 开发者 | 审核通过 / 下架删除 |
| `mod_del {id}` | 作者 / 开发者 | 删除自己的模块 |
| `mod_kv_get {id, key}` / `mod_kv_set {id, key, value}` | 模块运行期 | 模块存储，按 (模块, 用户) 隔离，每模块每用户最多 200 键 / 64KB |
| `mod_relay {mod, body}` → 广播 `mod_push` | 模块运行期 | 模块间的自定义消息，`body` ≤ 8KB，限速 10 秒 20 条 |

服务端存储位置：`data/modules/<id>/client.js`、`manifest.json`、`kv/<uid>.json`，
索引在 `data/modules/index.json`（400ms 合并写）。

## 4. 上传与审核流程

1. 「我的 → 模块 → 上传」：粘贴 manifest JSON 和 client.js 代码；
2. 普通用户上传 → 状态 `pending`，**只有自己和开发者能在市场里看到**；
3. 开发者（`DEV_UIDS`）在模块市场点「审核」→ 通过后才对所有人可见；
4. 作者可以重新上传同 id 覆盖（版本升级），改完仍是待审；
5. 想删：作者在开发者协助下用 `mod_del`（面板暂未暴露普通用户的删除入口）。

## 5. 现在还没有的东西

- **服务端模块代码**：模块不能往服务器塞自己的 JS。需要服务端逻辑只能通过 `mod_kv_*` +
  `mod_relay` 拼，或者直接来提 PR 走内置。
- **模块专属图标/图片资源**：目前只能用 emoji。
- **模块间通信**：`mod_push` 是全量广播，客户端自己按 `mod` 字段过滤；没有点对点通道。
- **热更新**：模块代码存在本地，重新上传后用户需要在市场里重新「安装」才会拿到新版。

## 6. 最小示例

`examples/modules/dice/client.js`（掷骰子：本地次数 + 服务端总次数）：

```js
var total = 0;
function mount(ctx) {
  ctx.setTitle('掷骰子');
  var mine = ctx.local.get('rolls', 0);
  ctx.el.innerHTML = '<p>本机掷了 <b id="lo">' + mine + '</b> 次</p>' +
    '<button id="roll">掷一次</button><p id="srv">服务端：读取中…</p>';
  document.getElementById('roll').onclick = function () {
    mine += 1; ctx.local.set('rolls', mine);
    document.getElementById('lo').textContent = mine;
    ctx.store.get('total', function (v) {
      total = Number(v || 0) + 1;
      ctx.store.set('total', total, function () {
        document.getElementById('srv').textContent = '服务端：' + total + ' 次';
      });
    });
  };
}
```
